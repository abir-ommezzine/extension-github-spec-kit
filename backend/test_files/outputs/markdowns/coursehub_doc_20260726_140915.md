# CourseHub - Technical Specification & Architecture Document

## 1. Executive Summary & Architecture Overview

### 1.1 Executive Brief
CourseHub is a course management platform API facilitating user authentication, course lifecycle management, and student enrollment tracking. The system implements a role-based access model (Student/Instructor) and manages the relational flow between Users, Courses, and Modules, with a specific focus on enrollment progress automation and strict deletion constraints to protect active learner data.

### 1.2 Maturity Assessment
The specification provides a high-quality technical contract with precise business rules and entity relationships. However, it lacks strategic context, specifically regarding overarching business goals and explicit scope boundaries, which could lead to implementation drift. Due to these structural gaps in the 'Why' and 'Out-of-Scope' definitions, the project status is REFINEMENT.

### 1.3 Technical Stack
* JWT
* Resend

### 1.4 Architectural Constraints
* Authentication: Mandatory JWT Bearer tokens in Authorization header.
* Response Format: Standardized envelope containing 'data', 'meta', and 'errors'.
* Data Validation: Enrollment progress must be an integer between 0 and 100 inclusive.
* Business Logic: Course deletion is forbidden if active enrollments exist (409 Conflict).
* Enrollment Logic: Students are restricted to published courses and unique enrollments per course.
* State Automation: `completed_at` must be automatically set to current timestamp when progress reaches 100.

### 1.5 Critical Dependencies
* Resend: Required for asynchronous welcome email delivery upon registration.
* JWT: Essential for identity verification and session management.
* Enrollment -> Course: Strict dependency ensuring students only enroll in published courses.
* Course -> Enrollment: Referential integrity constraint preventing course deletion if active enrollments are present.
* Course -> Module: Structural containment relationship for course content.

## 3. Detailed Technical Specifications & Business Rules

### 3.1 Requirements Traceability

| RULE-PROGRESS-RANGE | Constraint | Enrollment progress must be an integer between 0 and 100 inclusive. | PUT `/api/v1/enrollments/{enrollment_id}` |

### 3.2 Security Rules
* **Authentication**: All protected endpoints require a `Authorization: Bearer <token>` header using JWT.
* **Authorization**: Role-based access control is enforced (e.g., `FR-COURSE-CREATE` is restricted to the Instructor role).

### 3.3 Data Models
* **User (ENT-USER)**: Core identity containing email, display name, and role.
* **Course (ENT-COURSE)**: Content container with pricing and publication status.
* **Module (ENT-MODULE)**: Ordered content units belonging to a Course.
* **Enrollment (ENT-ENROLLMENT)**: Junction entity tracking the relationship and progress between a User and a Course.
